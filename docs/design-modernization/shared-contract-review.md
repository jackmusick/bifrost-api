# Shared contract reconciliation — 2026-09-10

This reconciles the shared list/table/card, pagination, picker, and overflow-action contracts against current source consumers and existing browser/component evidence. It distinguishes real row persistence from geometric or intercepted coverage. It is not a final candidate declaration.

## Table/card/list surfaces

The shared table primitive is `client/src/components/ui/data-table.tsx`. Its contract is a bounded scroll container with sticky header/footer, native table semantics, optional clickable rows, optional `href` modified-click support, and row-action shielding for links, buttons, inputs, labels, menu items, switches, comboboxes, contenteditable content, and selected text. `client/src/components/ui/data-table.test.tsx` exists and covers row-action shielding for nested link/button/checkbox controls, ctrl-click and middle-click `href` opening, caller mouseup preservation, and selected-text suppression. Sticky header/footer and parent-overflow geometry are still proven through consumers rather than a primitive geometry test.

## Remaining shared-contract gaps

- `DataTable` has focused primitive coverage for row-action shielding, modified-click `href`, caller mouseup, and selected-text suppression in `data-table.test.tsx`. Remaining primitive gap is sticky footer extraction and parent overflow geometry; those are currently covered through consumers such as Users, Organizations, Roles and Knowledge.
- `RecordActionsMenu` has no standalone test for propagation shielding and accessible trigger labelling. Consumer tests catch common regressions, but the shared primitive contract is implicit.
- `ApplicationListSurface` and `FormListSurface` lack sibling surface tests even though page tests cover their current users. Workflow has a focused surface test; apps/forms depend more on page-level tests.
- `GitHubResourceSelect` lacks a focused unit test; accepted GitHub settings browser evidence was intentionally intercepted for external GitHub data, so long-option wrapping/loading/disabled behavior is not proven by a real third-party route.
- Several read-only tables in reports, diagnostics, audit and history have route/component rendering coverage, but not a shared persistence claim; that is appropriate unless those surfaces gain row mutation actions.
