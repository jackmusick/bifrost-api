# Acceptance closure matrix

Scope: supported route families and settings panels from `client/src/App.tsx`, reconciled against the current core/admin/settings/resources/access-shell/shared inventories and checked-in acceptance specs. This is the denominator document. It does not claim every-click coverage; it separates primary browser journeys from lower-layer contracts and explicit external/provider limits.

Current targeted browser count: **56 passing journeys** in the ledger after Dashboard, SECURITY-02 recovery login, SECURITY-03 password change, role non-user assignment, and form builder persistence passed. Form deactivation and the retained Disabled card also passed after reload.

Evidence labels:

- **Primary browser**: checked-in `client/e2e` drives the rendered route against real local Bifrost services for the named action. If setup is intercepted, this is stated.
- **Lower-layer contract**: component, service, backend, or platform tests prove payloads, persistence, authorization, or edge behavior without full browser coverage.
- **External limit**: third-party providers, OAuth, passkeys, model calls, secure credential runner behavior, downloads, or external assistant installation are bounded to deterministic fixtures or lower-layer assertions.
- **Required gap**: a finite primary route action with no adequate current assertion, or with only structural smoke where persistence/action proof is needed.
