Scope: current settings routes and tabs in the design-system-modernization worktree. This is a source-and-test inventory, not a new acceptance claim. Heading-only smoke, route redirect checks, and navigation-shell tests are listed only as shell evidence, not as proof that a panel's actions are accepted.

## Cross-Cutting Evidence Notes

- `client/e2e/permissions.user.spec.ts` now targets the real `/config` route and verifies in-place denial plus return to member Home. It is permission-boundary evidence, not settings-panel acceptance.
- `client/e2e/preferred-sso.admin.spec.ts` proves preferred SSO redirect behavior from login after API seeding. It does not prove the Authentication settings UI can create or edit that preference.
- `client/e2e/branding-terminology.admin.spec.ts` and `client/e2e/design-foundations.admin.spec.ts` prove branding effects in the shell/navigation, not the Branding settings form lifecycle.
- `client/e2e/memory.admin.spec.ts` is the strongest checked-in cross-panel browser spec: it exercises platform memory, global and organization instructions, MCP resolution, user memory preferences, saved-memory persistence, and removal. Its platform settings route assumptions should be revalidated because current `Settings.tsx` registers Memory and Default MCP Instructions as separate tabs.
- Prior review documents, especially `docs/design-modernization/platform-settings-review.md` and `docs/design-modernization/account-settings-review.md`, contain substantial historical browser-review evidence. They are useful acceptance history, but they are not a substitute for checked-in specs when the goal is repository-test coverage.
